1. As correções de acessibilidade

Registro de correções de acessibilidade no código do Bootstrap
Componente Problema Como se detectou Correção Onde está no código
Botão do menu O nome acessível em inglês ("Toggle navigation"). Painel Accessibility no F12 mostrando o Name. Tradução para "Menu", mantendo a semântica. Atributo aria-label="Menu" no button.navbar-toggler.
Botão de fechar O nome acessível em inglês ("Close"). Painel Accessibility no F12 mostrando o Name. Tradução para "Fechar". Atributo aria-label="Fechar" no button.btn-close.
Título do diálogo Uso de h1 dentro do modal, quebrando a hierarquia da página. Recomendação da documentação do Bootstrap. Troca para h2, mantendo a classe visual. Tag <h2 class="modal-title h5">.
Ligação das mensagens O invalid-feedback não estava atrelado ao campo via ARIA. Apresentação do conceito aria-describedby na apostila. Vinculação dos IDs das mensagens aos campos. Atributo aria-describedby nos inputs.
Role do diálogo O validador W3C não reconhece aria-labelledby sem papel. Erro apontado pelo validador do W3C. Adição manual do papel de diálogo. Atributo role="dialog" no div.modal.

Pendências declaradas:

  • Foco após o erro: O foco permanece no botão de envio ("Fazer pedido"). Para movê-lo ao primeiro campo com erro, seria necessário um programa JavaScript customizado.
  • Conteúdo dinâmico no modal: O modal está fixo para o produto "Açaí". Para que ele mostre as informações de outros produtos, seria necessário um script para injetar o conteúdo dinamicamente.

2. O registro de decisão

Contexto

A AgroFeira precisa definir sua base de estilização para a aplicação em React (encontros 11+). O site autoral tem 6,9 kB de CSS (e 433 kB no total), enquanto o Bootstrap tem 35,6 kB de CSS (e 425 kB no total). O peso do script do Bootstrap é de 80,5 kB (25,2 kB transferidos). Sem o script do Bootstrap, a barra de navegação no celular e o diálogo param de funcionar.

Opções consideradas

  • Folha autoral: Ganha controle total e leveza (6,9 kB de CSS). Cobra mais tempo de escrita manual de cada regra.
  • Bootstrap: Ganha componentes prontos e validação (35,6 kB de CSS e 80,5 kB de JS). Cobra um peso maior e a dependência de um script que pode conflitar com o React.
  • Tailwind: Ganha a velocidade de escrever utilitários direto no HTML (conforme slides). Cobra uma mudança de paradigma e a necessidade de configurar o build, além de não prover o script de comportamento (como o modal do Bootstrap).

Decisão

Usar a folha autoral para a base do React, aproveitando os tokens (tokens.css) já criados.

Consequências aceitas

  • Teremos que escrever os componentes do zero (como o botão e os cards), sem a velocidade de prototipagem do Bootstrap.
  • Não teremos o script pronto de validação de formulário e de modais, exigindo mais linhas de JavaScript (ou o uso de bibliotecas React específicas).

O que me faria mudar de ideia

Se o tempo de desenvolvimento do projeto for muito curto, e o peso do Bootstrap (35,6 kB de CSS + 80,5 kB de JS) não impactar negativamente o LCP da aplicação final em React.
